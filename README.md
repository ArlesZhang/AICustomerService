# 智能客户服务系统

本项目研究的，不只是“客服机器人怎么回答问题”，而是类似晓多、乐言的系统如何完成以下完整闭环：

1. 接待与理解： 识别意图、商品、订单和客户诉求。
2. 知识与决策： 检索商品资料、理解售后政策、判断能否自动处理。
3. 业务执行： 调用订单、物流、库存、退款等系统。
4. 风险控制： 处理低置信度、投诉、越权、失败重试和人工接管。
5. 运营评估： 统计机器人解决率、转人工率、回答准确率、客户满意度、响应时延与单次会话成本。
6. 持续优化： 从未解决会话和人工纠正中发现知识缺口、流程缺陷与模型 Bad Case，再更新知识库、规则和 Prompt。

### 第一个可运行的客服工作流

先不接大模型，也不追求“智能体自主思考”。第一步是做出一个可验证的最小系统：
1. 接收客户问题。
2. 识别问题类型。
3. 根据类型进入商品咨询、订单咨询或退款咨询节点。
4. 生成回复或转人工。
5. 返回完整处理结果。

这一步的价值在于先把业务边界和执行链路跑通。

### 编写模拟业务工具

这里有一个非常重要的设计原则：

查询资格不等于执行退款。

真实系统必须把“检查是否符合条件”和“调用退款接口”分开。即使模型判断客户很合理，也不能因此绕过平台退款规则、账号权限和必要审批。
