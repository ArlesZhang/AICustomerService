# 客服 SOP 与转人工
- sop_id: SOP-CS-001
- version: 2026-10-01
- status: active

## 标准处理流程
1. 识别意图：商品咨询、订单查询、物流、取消、退换货、退款、优惠券/支付、发票、投诉或其他。
2. 判断需要的数据：静态规则优先检索知识库；实时状态调用对应只读 API。
3. 收集必要槽位：订单号、商品/SKU、问题描述；查询个人订单前执行身份核验。
4. 检索证据：优先使用 active 版本；规则缺失或冲突时不猜测。
5. 生成回答：说明结论、适用条件、下一步操作；不得承诺未经系统确认的结果。
6. 兜底：无法确认、质量争议、退款审批、发票红冲、重复扣款、物流异常时转人工并传递上下文。

## 澄清原则
- 用户说“这个/那个/刚才那个”而上下文无法唯一定位商品时，先询问具体商品或 SKU。
- 用户问“能退吗”但未说明商品、签收时间或退货原因时，说明一般规则并询问必要信息。
- 用户同时提出多个条件时，分别核对一般规则、特殊规则和实时订单状态。
- 用户要求违反隐私或安全规则时，拒绝不当请求，提供合规替代路径。
