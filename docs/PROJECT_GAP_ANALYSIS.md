# 项目完成度与差距分析

> 最后更新：2026-10-28  
> 说明：本文中的百分比是**工程进度估算**，用于排优先级，不是效果指标。真实效果必须以 V2 评测集和线上数据为准。  
> 行业标杆部分列的是晓多、乐言、飞鸽等产品的**常见能力面**，不同厂商和版本存在差异，不代表对某一家产品的逐条复刻。

## 1. 结论

- 当前项目完成的是**可运行的知识问答 MVP**：Dify RAG + LangGraph `knowledge` 节点 + 多轮会话 + 异常降级 + FastAPI。
- 已获得一套 50 条合成基准数据包（`xq-cs-benchmark-1.0`），含 6 份知识文档和 mock 业务数据；V2 评测有了输入，但评测脚本与闭环尚未建立。
- 与行业标杆的差距不在“能不能回答一个问题”，而在：知识治理、评测闭环、业务执行、人机协同、监控与商业化。
- 对照本项目六步闭环：第 1、2 步部分完成；第 3 步只有 mock；第 4 步有基础降级；第 5、6 步基本未开始。
- 当前最优先的不是继续加功能，而是建立可重复的评测基线。

## 5. 最需要优先收敛的 5 个 Gap

1. **有 50 条评测集，但没有评估脚本和基线结果**：无法量化意图准确率、检索召回、回答正确率和转人工率，调优仍无法对比。
2. **知识文档已具备，但治理缺失**：6 份文档尚无知识资产表、元数据、版本和生效/失效管理，RAG 调优不可复现，新旧政策容易冲突。
3. **真实业务 API 未接入**：订单、物流、退款仍是 mock，系统只能“回答问题”，不能真正“办事”。
4. **人机协同未建立**：没有工作台、接管上下文、工单流转，转人工只是一个状态字段。
5. **运营指标与成本未建立**：没有解决率、转人工率、CSAT、P95、单次成本，无法证明商业价值。

## 6. 建议的差距收敛路径

| 阶段 | 重点 | 预期产出 |
| --- | --- | --- |
| 第 1 步 | 冻结 V1 + 建立评测基线 | V1 tag、50+ 测试集、评估脚本、基线报告 |
| 第 2 步 | 知识治理与 Bad Case 闭环 | 知识资产表、版本记录、Bad Case 归因表、回归用例 |
| 第 3 步 | 只读业务工具 | 订单/物流/商品/售后模拟 API + 工具调用 + 权限校验 |
| 第 4 步 | 任务编排与人机协同 | 槽位收集、审批、流程恢复、人工接管上下文 |
| 第 5 步 | 安全、监控与商业化 | 鉴权/限流/审计、Trace/看板/告警、A/B 与 ROI |

> 这是建议顺序，不是时间承诺。每一步应以“可运行、可测试、可复现”为验收标准。
